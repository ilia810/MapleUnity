# Asset work on the MacBook

The Windows PC handles game code, Unity integration and runtime verification.
The MacBook handles drawing, asset repair and editable art sources. GitHub is the
shared handoff: https://github.com/ilia810/MapleUnity.

## First setup

Clone the repository on the Mac, then add the resulting `MapleUnity` folder as a
local project in Codex:

```sh
git clone https://github.com/ilia810/MapleUnity.git
cd MapleUnity
git switch -c art/menu-buttons
```

Drawing PNGs and editing art sources does not require Unity. To import or preview
the game, use Unity **2023.2.20f1**. Windows is the validated runtime; macOS game
execution has not been verified. Most original game art is loaded from external
NX archives, which are intentionally excluded from Git. The nine supplied UI
reference screenshots and the current menu-button PNGs are included in Git and
can be edited immediately without those archives.

There are twelve PNGs: `BtShop`, `BtMenu` and `BtShort`, each with the suffixes
`-normal`, `-mouseOver`, `-pressed` and `-disabled`. They are **148 × 68** transparent
RGBA images displayed at **74 × 34** HUD pixels. Keep these file names, canvas
sizes, alignment and alpha transparency when replacing them. Captions are part
of the art: **CASH SHOP**, **MENU**, **SHORT CUT**. Keep them crisp and readable at
the actual display size. Check all states together to avoid unintended jumps;
the pressed face currently moves by one HUD pixel (two texture pixels).

The current normal faces were cropped from the reference screenshot, and their
interaction states were generated by a local script. They were not hand-painted.
`Tools/Build-ClassicHudButtons.ps1` regenerates and overwrites all twelve PNGs from
that screenshot. After manual painting, do not run it over the revised assets.
Retain an editable source alongside the exports and update the provenance note.

## Daily collaboration

- Start each art task from an up-to-date `master`, with a separate `art/...`
  branch. Use `git pull --ff-only` while on a clean `master` before branching.
- Save layered/editable sources under `ArtSource/<feature>/`. Export runtime PNGs
  into the agreed folder under `Assets/`. New exports need their own asset path;
  the Windows code task can connect them to the game.
- Preserve existing `.meta` files and their GUIDs. Never delete and regenerate
  metadata for a replacement image. For new assets, commit the `.meta` generated
  by Unity; if Unity is not installed on the Mac, flag the new files so the PC
  can import them and commit their metadata during integration.
- Keep art branches focused on assets and accompanying notes. Ask the PC code
  task to handle changes to C#, scenes, prefabs, import settings or project settings.
- Commit completed art and push its branch. Keep Unity caches, logs and NX
  archives out of commits. If an editable source approaches GitHub's file-size
  limit, arrange Git LFS before committing that file.
- Give the PC task the branch name, changed paths, intended import/display size,
  and any integration requests. The PC reviews and merges the branch, tests the
  actual game and shares rendered feedback. Pull the merged `master` before
  starting the next art branch.

For the first button branch, after reviewing `git diff` and `git status`, stage
the specific images/source files you changed, then:

```sh
git commit -m "Refine classic menu button artwork"
git push -u origin art/menu-buttons
```
